# Lab ch05. Python 3.12. Exact versions, as installed on 2026-10-29 (`pip freeze`, then edited
# as described below). Install with `pip install -r requirements.txt` into a fresh virtual environment.
#
# Direct dependencies: mcp (the Model Context Protocol Python SDK), a2a-sdk (the A2A Python SDK),
# opentelemetry-sdk and opentelemetry-exporter-otlp-proto-http (tracing), PyYAML and jsonschema (the
# golden set and the manifests), litellm and the packages its proxy needs (the model gateway; fastapi,
# openai, tiktoken and friends), starlette and uvicorn (the MCP HTTP transport, the A2A agent, the
# fake backends, the runtime adapter), httpx, pytest. Everything else is transitive. Two httpx lines
# are not a mistake: mcp depends on the `httpx2` distribution and a2a-sdk and litellm on `httpx`.
#
# Three edits to the freeze, all deliberate:
# - `litellm-enterprise` is left out. `pip install "litellm[proxy]"` pulls it in, and its license is
#   proprietary (License-Expression: LicenseRef-Proprietary, "The BerriAI Enterprise license"). The
#   proxy imports it only inside `try/except ImportError`, and every test passes without it. This file
#   lists litellm without the [proxy] extra, so pip never asks for it. Do not add the extra back.
#   litellm itself and litellm-proxy-extras are MIT.
# - pywin32 carries the same marker mcp and azure-identity put on it; it exists only on Windows.
# - uvloop is added, with the marker the [proxy] extra puts on it. A Windows freeze cannot contain it,
#   yet on every other platform the proxy's CLI hands uvicorn `loop="uvloop"` with no way to say
#   otherwise, so without it `litellm` dies at startup with "No module named 'uvloop'". MIT; the
#   version is the latest on PyPI on the freeze date.
